ПРОМТ: ДОДЕЛАТЬ АВТООБНОВЛЕНИЕ TSUZUKI (ПК + ANDROID TV + ТЕЛЕФОН)
Скопируй всё ниже линии в чат с ИИ и приложи папку «Исходники» (или нужные файлы).
В конце файла — что нужно сделать тебе руками (GitHub).

────────────────────────────────────────────────────────────────────────

Ты — опытный разработчик на Electron и Android (Java). Помоги мне доделать
автообновление в моём приложении Tsuzuki (трекер аниме). Работай аккуратно,
по шагам, каждый изменённый кусок помечай комментарием «// ИЗМЕНЕНО В 1.6: …».

=== ЧТО ЗА ПРОЕКТ ===
Три папки:
- tsuzuki-src        — ПК-версия (Electron 45, Windows + Linux). Без npm-зависимостей
                       во время работы: никаких electron-updater и прочих библиотек.
- tsuzuki-tv-src     — Android TV (WebView + Java-мост NativeBridge.java,
                       интерфейс копируется из tsuzuki-src/src/renderer скриптом sync-www.sh).
- tsuzuki-phone-src  — Android-телефон (тот же интерфейс; android-api.js, tv-nav.js
                       и tv.css берёт из ../tsuzuki-tv-src/tv-web через sync-www.sh).
Сейчас версия 1.5.0 (ТВ versionCode 7, телефон versionCode 4).

=== ЧТО УЖЕ ЕСТЬ ===
ПК (tsuzuki-src/src/main/services.js, раздел «Автообновление»):
- раз в 6 часов (main.js, setInterval) читает version.json по адресу
  settings.UPDATE_JSON_URL (сейчас пусто = выключено) формата
  { "version": "1.5.0", "url": "https://…/Tsuzuki-Setup.exe", "notes": "…" };
- если версия новее — сам качает установщик во временную папку
  (Tsuzuki-Setup-<версия>.exe), показывает плашку «Обновление X скачано — перезапустить?»;
- по кнопке запускает установщик с ключом /S и закрывает приложение;
- работает только в собранной версии (app.isPackaged).
Интерфейс: src/renderer/api/updater.js (плашка), пункт настроек autoUpdate (custom.js).
Установщик NSIS: tools/build-installer.nsi — умеет тихую установку (IfSilent),
сам закрывает запущенный Tsuzuki (taskkill), ставит в %LOCALAPPDATA%\Programs\Tsuzuki.

Android (tsuzuki-tv-src/tv-web/android-api.js):
- var UPDATE_URL = '' — адрес version.json формата
  { "versionCode": 7, "versionName": "1.5.0", "apk": "https://…apk", "notes": "…" };
- checkUpdates сравнивает versionCode с B.getVersionCode();
- installUpdate → NativeBridge.downloadAndInstall(url): качает APK (только https)
  и открывает системную установку через FileProvider; если нет разрешения
  «Установка неизвестных приложений» — просит его; при ошибке открывает ссылку в браузере.
- updater.js запускает проверку на Android через 15 секунд после старта.

=== ЧТО НУЖНО СДЕЛАТЬ ===

ЗАДАЧА 1. Linux: не запускать .exe.
Сейчас на Linux автообновление скачало бы Windows-установщик и попыталось его запустить.
Сделай так:
- на Linux (process.platform !== 'win32') ничего не скачивать;
- если версия новее — плашка «Доступна версия X» с кнопкой «Скачать»,
  которая открывает в браузере страницу релиза (shell.openExternal);
- адрес страницы — новое поле "page" в version.json
  (если его нет — открыть "url_linux", если и его нет — "url");
- Windows-логику не ломать.

ЗАДАЧА 2. Разные адреса для ТВ и телефона.
Сейчас ТВ и телефон берут один UPDATE_URL, а versionCode и APK у них разные
(телефон с versionCode 4 «обновился» бы на ТВ-APK).
- В android-api.js сделай две переменные: UPDATE_URL_TV и UPDATE_URL_PHONE;
- выбирай по window.__deviceType ('phone' → телефонный, иначе ТВ);
- старое имя UPDATE_URL убери или оставь как запасное с пометкой.

ЗАДАЧА 3. Проверка скачанного файла (безопасность).
Автообновление запускает чужой файл из интернета — нужно убедиться, что он настоящий.
- Добавь в version.json (и в оба Android-json) поле "sha256" — SHA-256 файла в hex;
- ПК: после скачивания посчитай SHA-256 (crypto) и сравни; не совпало —
  удалить файл, статус 'error', ничего не запускать;
- Android: то же в NativeBridge.downloadAndInstall (MessageDigest) до открытия установки;
- разрешай скачивание только по https и только с хостов из списка
  (github.com, objects.githubusercontent.com, release-assets.githubusercontent.com) —
  список вынеси в settings.js / android-api.js, чтобы я мог добавить свой сайт;
- если поля sha256 в json нет — для обратной совместимости ставить, но в лог писать предупреждение.

ЗАДАЧА 4. Перезапуск после обновления (ПК).
Сейчас после тихой установки Tsuzuki закрывается и сам не открывается.
- В tools/build-installer.nsi добавь Function .onInstSuccess: если установка тихая
  (IfSilent) — запустить "$INSTDIR\Tsuzuki.exe" (Exec);
- после запуска новой версии один раз показать тост «Tsuzuki обновлён до X»
  (сравнить сохранённую версию в store с текущей).

ЗАДАЧА 5. Выключатель «Автообновление» должен реально выключать.
Сейчас пункт autoUpdate в настройках влияет только на плашку,
а главный процесс всё равно проверяет и качает каждые 6 часов.
- Передавай значение пункта в главный процесс (ipc, например 'updater:setAuto');
- выключено → не проверять по таймеру и не качать в фоне;
  ручная кнопка «Проверить обновления» в настройках работает всегда.

ЗАДАЧА 6. Кнопка и статус в настройках.
В «Настройках» (views/settings.js) должен быть блок «Обновления»:
- текущая версия;
- кнопка «Проверить обновления» → показывает: «Последняя версия», «Доступна X» (+ notes),
  «Скачивается N%», «Готово — перезапустить», «Ошибка, попробуй позже»;
- на Android — то же, кнопка «Обновить» вызывает installUpdate.
Если блок уже есть — проверь, что все статусы отображаются.

ЗАДАЧА 7. Адреса (впиши, ник подставлю я).
- ПК: settings.UPDATE_JSON_URL =
  'https://github.com/НИК/tsuzuki-releases/releases/latest/download/version.json'
- ТВ: UPDATE_URL_TV =
  'https://github.com/НИК/tsuzuki-releases/releases/latest/download/version-tv.json'
- Телефон: UPDATE_URL_PHONE =
  'https://github.com/НИК/tsuzuki-releases/releases/latest/download/version-phone.json'
Ссылка /releases/latest/download/<имя файла> всегда ведёт на последний релиз,
поэтому имена файлов в каждом релизе одинаковые, без номера версии.

ЗАДАЧА 8. Скрипт выпуска релиза.
Сделай tools/make-release.mjs (Node, без зависимостей), который:
- берёт версию из package.json, versionCode/versionName из обоих app/build.gradle;
- находит собранные файлы (dist/Tsuzuki-Setup-<версия>.exe, APK ТВ и телефона)
  и копирует их в папку release/ под постоянными именами:
  Tsuzuki-Setup.exe, Tsuzuki-TV.apk, Tsuzuki-Phone.apk;
- считает SHA-256 каждого;
- пишет release/version.json, release/version-tv.json, release/version-phone.json
  (с полями version/versionCode, versionName, url/apk, page, sha256, notes);
- notes берёт из аргумента или файла release-notes.txt;
- в конце печатает, что загрузить в GitHub Release.
Также: APPVERSION и VIProductVersion в build-installer.nsi брать из package.json
(или сделать так, чтобы скрипт напоминал их поменять).

ЗАДАЧА 9. Документация и политика.
- CHANGES-1.6.md: что изменилось;
- README: раздел «Как выпустить обновление» по шагам;
- политика конфиденциальности (views/privacy.js, раздел 2): приложение раз в несколько
  часов обращается к github.com за файлом версии; GitHub видит IP и название приложения;
  проверку можно выключить в настройках.

ЗАДАЧА 10. Как проверить (опиши и по возможности сделай тест).
- ПК: поднять локально version.json с версией 9.9.9 (временно разрешить
  http://localhost только в режиме разработки), убедиться: скачалось, sha256 сошёлся,
  плашка появилась; с неверным sha256 — файл не запускается.
- Linux: вместо скачивания открывается страница релиза.
- Android: поставить сборку с меньшим versionCode, выложить json с бо́льшим,
  проверить ТВ и телефон по отдельности (каждый получает свой APK).

=== ПРАВИЛА ===
- Не трогай файлы, не связанные с задачей (в том числе kodik.js и adblock*.js).
- Никаких новых npm-библиотек и Android-библиотек, кроме уже подключённых.
- Версию поднять до 1.6.0; ТВ versionCode 8, телефон versionCode 5.
- Не меняй ключ подписи (tsuzuki.keystore) и applicationId — иначе обновление
  не встанет поверх старой версии.
- После правок в интерфейсе напомни запустить sync-www.sh в обоих Android-проектах.
- Отдай изменённые файлы с полными путями и короткий список: что, где и зачем.

ЧТО СДЕЛАТЬ ТЕБЕ РУКАМИ (GitHub)

1. Зарегистрируйся на github.com (если ещё нет) и создай ПУБЛИЧНЫЙ репозиторий
   tsuzuki-releases (исходники туда класть не обязательно).
   Из приватного репозитория файлы без входа не скачать — обновление не сработает.
2. Подставь свой ник вместо НИК в адресах из задачи 7.
3. Выпуск каждой версии:
   а) поднять версию (package.json, оба build.gradle, build-installer.nsi);
   б) собрать exe и оба APK (ключ подписи — всегда тот же tsuzuki.keystore!);
   в) запустить node tools/make-release.mjs;
   г) на GitHub: Releases → Draft a new release → тег v1.6.0 → перетащить
      все 6 файлов из папки release/ → Publish release.
   Через несколько часов (или по кнопке «Проверить обновления») приложения
   увидят новую версию.
4. Храни tsuzuki.keystore и пароль от него в надёжном месте (лучше 2 копии).
   Потеряешь ключ — пользователи не смогут обновиться без удаления приложения.
5. Помни: GitHub может удалить репозиторий, если в приложении есть пиратские
   источники видео. Для такой сборки лучше свой хостинг — тогда в списке
   разрешённых хостов (задача 3) укажи свой сайт.
6. На ПК автообновление работает только у тех, кто ставил через Tsuzuki-Setup.exe,
   а не распаковал zip.
