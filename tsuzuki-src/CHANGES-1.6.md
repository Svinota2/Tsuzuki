# Изменения 1.6.0 (07.11.2026)

Доделано автообновление (ПК + Android TV + телефон) — то, что было вынесено
в отдельный файл «Промт-автообновление-Tsuzuki.txt». Без новых npm- и
Android-библиотек; Kodik, подбор токенов, блокировка рекламы не тронуты.

## ПК (Windows/Linux): автообновление

Файлы: `src/main/services.js` (раздел «Автообновление»), `src/main/main.js`,
`src/main/preload.js`, `src/main/settings.js`, `src/renderer/api/updater.js`,
`src/renderer/views/settings.js`, `src/renderer/custom.js`, `tools/build-installer.nsi`.

- **Linux больше не пытается запустить .exe** (задача 1). На Linux приложение
  ничего не качает: сравнивает версию и показывает «Доступна версия X» с кнопкой
  «Скачать», которая открывает страницу релиза в браузере (`page` из version.json,
  затем `url_linux`, затем `settings.UPDATE_PAGE`). Windows-логика не изменилась.
- **Проверка SHA-256** (задача 3). В version.json добавлено поле `sha256`;
  после скачивания установщик сверяется по SHA-256, не совпало — файл удаляется,
  статус `error`, запуска не происходит. Если `sha256` нет (старые файлы) —
  скачивание разрешено, в лог пишется предупреждение.
- **Только https и белый список хостов.** `settings.UPDATE_ALLOWED_HOSTS`:
  github.com, objects.githubusercontent.com, release-assets.githubusercontent.com.
  Для запуска из исходников разрешён `http://localhost` (только локальные тесты).
- **Выключатель «Проверять обновления автоматически» реально выключает** (задача 5).
  Настройка передаётся в главный процесс (`updater:set-auto`), таймер проверки
  живёт в `services.setUpdaterAuto()`: выключено — фоновая проверка и скачивание
  не запускаются вовсе; ручная кнопка работает всегда.
- **Перезапуск после тихой установки** (задача 4). В `build-installer.nsi` добавлен
  `Function .onInstSuccess`: при `/S` после установки запускается
  `"$INSTDIR\Tsuzuki.exe"`. После запуска новой версии один раз показывается тост
  «Tsuzuki обновлён до X» (сравнение с версией, сохранённой в localStorage).
- **Кнопки и статусы в «Настройках»** (задача 6). Блок «Обновления» показывает:
  текущую версию, «Проверяем…», «Доступна X», «Скачивается N%», «Готово — перезапустить»,
  «Ошибка, попробуй позже»; кнопки «Проверить обновления», «Перезапустить и обновить»
  (когда скачано), «Скачать (страница релиза)» (Linux) или «Скачать обновление» (Android).
  Текст статуса обновляется «на лету» по событию `tsuzuki:update`.

## Android (ТВ и телефон)

Файлы: `tsuzuki-tv-src/tv-web/android-api.js`, `NativeBridge.java` (общий для обоих
проектов — скопирован в телефонный проект), `EpisodesWorker/Checker` не менялись.

- **Разные адреса version.json для ТВ и телефона** (задача 2):
  `UPDATE_URL_TV` и `UPDATE_URL_PHONE`, выбор по `window.__deviceType`
  (`phone` → телефонный, иначе ТВ). Старое `UPDATE_URL` оставлено запасным.
- **Проверка SHA-256 APK** (задача 3): `downloadAndInstall(id, url, sha256)` —
  после скачивания считает SHA-256 (MessageDigest) и при несовпадении удаляет файл,
  установку не открывает. Пустой sha256 в json — установка с предупреждением в лог.
- **Только https и разрешённые хосты** для APK (`UPDATE_ALLOWED_HOSTS` в android-api.js).
- Версия: ТВ `versionCode 8`, телефон `versionCode 5`, versionName 1.6.0.

## Адреса и выпуск релиза

- `src/main/settings.js`: `UPDATE_JSON_URL`, `UPDATE_PAGE`, `UPDATE_ALLOWED_HOSTS`,
  `UPDATE_INTERVAL_HOURS` (6 ч). В адресах стоит `НИК` — замени на свой ник на GitHub.
- `tsuzuki-tv-src/tv-web/android-api.js`: `UPDATE_URL_TV`, `UPDATE_URL_PHONE`.
- **Новый скрипт `tools/make-release.mjs`** (задача 8): берёт версию из package.json
  и versionCode/versionName из обоих build.gradle; находит установщик и APK;
  копирует их в `release/` под постоянными именами `Tsuzuki-Setup.exe`,
  `Tsuzuki-TV.apk`, `Tsuzuki-Phone.apk`; считает SHA-256; пишет `version.json`,
  `version-tv.json`, `version-phone.json` (version/versionCode, versionName, url/apk,
  page, sha256, notes); синхронизирует APPVERSION/VIProductVersion в NSI;
  печатает, какие 6 файлов загрузить в GitHub Release.

## Что осталось тебе (GitHub)

1. Создать публичный репозиторий `tsuzuki-releases` (приватный не подойдёт —
   файлы не скачаются без входа).
2. Заменить `НИК` в адресах (см. выше) на свой ник.
3. Для каждого релиза: поднять версии → собрать → `node tools/make-release.mjs --repo "ник/tsuzuki-releases"`
   → загрузить 6 файлов из `release/` в GitHub Release с тегом `vX.Y.Z`.
4. Хранить `tsuzuki.keystore` и пароль в двух местах: без него обновления APK
   не встанут поверх старой версии.
